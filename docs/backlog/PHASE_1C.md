## Known gaps (recorded honestly, not hidden)

1. **No real-Postgres/Redis run of this phase's five new stores or routes yet.** Same shape as Phase 1B's gap 1: the stores are reviewed against the exact RLS pattern already proven elsewhere, and the route tests exercise the full API-to-service path with fakes, but nothing has run `transcripts`/`transcript_segments`/`script_versions`/`metadata_versions`/`chapter_versions` through a live, RLS-enforced Postgres this session. CI's `ci-python` job runs real Postgres/Redis service containers against the full suite including the RLS meta-test, which narrows this once that run is green.
2. **`youtube_captions` and `local_whisper` are not wired up.** Both are real methods on `TranscriptService` that raise `TranscriptSourceUnavailableError` rather than working, per spec feature 22's own allowance ("built and time-boxed but is not a PASS blocker for Phase 1C"). `youtube_captions` needs a caption-download scope and format not yet verified (OQ-21, new); `local_whisper` needs `faster-whisper`, which this sandbox cannot install (no PyPI access). Neither gets a route, since a route that always answers 501 is noise, not a capability.
3. **No "current version" pointer columns on `videos`.** Spec §7 describes `videos` carrying pointers to each artifact's current version; this phase instead gives each version table its own `is_current` flag per video (ADR 0014 decision 4), since nothing in Phase 1C needs one frozen combination of version ids - only Phase 1D's `publish_snapshots` does. Recorded as a deliberate scope line, not an oversight; Phase 1D must introduce the real pointer mechanism it needs rather than assuming one already exists on `videos`.
4. **No video-existence check on these routes.** A transcript/script/metadata/chapter version can be created against any `video_id`, including one that doesn't exist in `planning`'s `videos` table - RLS still scopes every row to the caller's workspace, but there is no foreign-key or application-layer check that the video is real. Consistent with how `channel_videos`/`recommendations` (Phase 1A) also carry an unchecked `video_id`/`channel_id` reference; a dedicated cross-module existence check is deferred rather than invented ad hoc for this phase.
5. **Chapter generation is an even-slice heuristic, not topic detection.** `generate_draft_chapters` titles chapters from the nearest transcript text at evenly spaced timestamps; it satisfies "generated from a transcript version" literally, but a creator should expect to retitle/reposition the draft before publishing (which the existing "editable before publish" edit/restore machinery already supports).
